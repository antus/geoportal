id: GP-297
title: Registering a service turns on the proxy by itself when the browser cannot read it
area: interop
priority: P1
status: done
depends: [GP-939, MK-128]
estimate: [2, 3]
legacy: R-297
acceptance:
  - Saving a service whose server sends CORS headers keeps the proxy off and its layers are listed.
  - Saving a service without CORS headers, with the proxy off, turns the proxy on and shows a notice saying so; its layers are then listed through the proxy.
  - A server that answers with an error page instead of capabilities is not considered readable, from the browser or the proxy.
---

Whoever adds a service should not have to know in advance whether its server sends CORS headers. When a
service is saved without the proxy, the catalog checks whether **the browser** would be allowed to read
its capabilities: the server reaches more than the browser, so the check does not ask whether the
server reads them, but whether the answer allows the origin of the shell (CORS) and the content security
policy of the shell lets the browser contact the service (MK-128). If not, and the capabilities are
read, the proxy is switched on with a notice. A response counts only if it contains capabilities.

  checks of the proxy with the `Origin` of the shell, and the browser is taken to read them only when the
  answer is capabilities, allows that origin with CORS, and the origin of the service is in the
  `connect-src` of the policy the kernel serves the shell with (MK-128, read from the kernel itself). The
  earlier idea of reading from the browser and falling back to the proxy is dropped: with the policy of
  MK-128 a browser read of an unlisted origin is blocked before any CORS, and the server can tell both
  reasons at once. Otherwise the proxy is turned on and the answer and the page say why (`cors`, `csp`);
  an error page is `unreadable` and changes nothing. Tests tagged GP-297: `tests/auto-proxy.spec.ts` on
  the bench restarted with the policy on (stubs with and without CORS, listed and not listed, an error
  page; the browser shows the layers directly or through the proxy, and is blocked where the check says
  so), `BrowserProbeTest`, `BrowserAccessTest`.

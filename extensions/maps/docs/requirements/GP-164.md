acceptance:
  - A GeoJSON, CSV, database or stream layer with a declared start field (and optional end field) gets the time control of the map, with the values taken from its features.
  - Moving the timeline shows only the features whose instant or interval touches the current window; features without a date stay visible.
  - A WFS layer with a time field sends the window as a filter to GeoServer instead of filtering in the browser.
  - The time field saved with the map is restored when the map is reopened.
---

The timeline already exists for WMS layers with a TIME dimension. Vector layers need to declare which attribute is time: a start field makes each feature an instant, start and end make it an interval. The map then filters features on the current window and reuses the same time bar; the dashboard time filter wins when the map is embedded in a dashboard. Half of the known use cases are time series. Rules: the field is declared, not guessed; features without a date stay on; a cap on distinct values keeps the bar usable.

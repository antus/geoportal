  - Creating an organization creates its GeoServer workspace, and a dataset loaded into it is answered by WMS GetCapabilities and WFS GetFeature of that workspace only.
  - A projected vector file loaded through Geoportal lands in PostGIS in its declared reference system, and WFS returns coordinates that match the source.
  - A layer or style changed in GeoServer by hand is brought back to the definition held by Geoportal at the next alignment.
  - A connection shared "to use" lets another person add its layers to a map without ever receiving its credentials in any answer.
---

Geoportal keeps GeoServer aligned with its catalog: one workspace per organization, with the stores,
layers and styles created and updated through the GeoServer REST API, never by hand. Loading follows
the decision of the F0 proofs: Geoportal converts the file (with its reference system checked) and
writes vectors straight into PostGIS, then publishes the layer with one REST call; the Importer leaves
the main path. Rasters are published as COG, on disk in the portable and in the object store on the
server. Connections to external services become catalog resources that can be shared to use or to
manage, while their credentials stay in Geoportal.

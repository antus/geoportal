title: The format of a data source and the way it arrives are separate properties
area: data
priority: P1
status: proposed
depends: [EXT-013]
estimate: [10, 15]
legacy: R-314
acceptance:
  - A GeoJSON given by URL becomes a data source with owner, tags and sharing, listed in the catalog under the GeoJSON type, and reusable in any map.
  - A 3D Tiles asset given by an ion asset id and token becomes a data source whose token never appears in API answers; only its presence is reported.
  - A remote source refuses a non-http address, an ion asset for a format other than 3D Tiles, and a request with neither address nor asset.
  - The first step of "New data" offers "A file", and the question of where it comes from (upload, URL, ion) is asked on the second step.
---

The same format entered by three doors and only one produced a data source: an uploaded GeoJSON became a
source with owner, tags, sharing and rights, while a GeoJSON by URL or a 3D Tiles ion asset stayed a
layer inside one map, not reusable, not shared, not listed, and the ion token ended up in a layer
configuration. Two independent axes were collapsed: **what it is** (the format, which is the type) and
**where it comes from** (uploaded, remote, ion), now a property of the source, with the address or asset
next to it and the secret stored where credentials are governed. From then on a remote source is a
source like any other.

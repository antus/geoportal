id: GP-187
title: A layer follows an operational table through change data capture instead of polling
area: data
priority: P2
status: proposed
estimate: [8, 12]
legacy: R-187
acceptance:
  - An insert, update or delete committed in the source table appears on an open map within seconds, without the map re-querying the table.
  - The number of queries received by the source does not grow with the number of open maps.
  - After a restart of Geoportal the layer resumes from the last applied change without gaps.
---

A layer follows an operational table without querying it at intervals: the transaction log of the database is read and the changes are applied. It is the honest alternative to the refresh policy (GP-052) when "every thirty seconds" means thirty queries a minute on a table of a hundred million rows: the load on the source becomes constant instead of growing with the number of open maps. Changes arrive as a stream, so the existing real-time layer carries them.

acceptance:
  - A WMS layer set to refresh every 30 seconds sends a new GetMap request to GeoServer about every 30 seconds while the map is open, and none after the map is closed.
  - A WFS or SQL layer set to refresh on view change requests only the features of the new extent after the view moves.
  - The reader sees the time of the last update of each refreshing layer and a "refresh now" command that triggers an immediate reload.
  - A dashboard widget whose source has a refresh interval shows new values from the source without reloading the page.
---

The map author chooses how each layer stays current, whatever its kind (WMS, WMTS, XYZ, WFS, GeoJSON from a URL or file, SQL, 3D Tiles, streams): at a fixed interval, on view change where the source can filter by extent, or by push where the source sends updates itself, with a chosen redraw cadence. The reader sees when the layer was last updated and can refresh it on demand. The same property applies to the source of every dashboard widget. One property turns a static map into a monitoring map. In the new product the policy is a layer property saved with the Geoportal map and applied by the Geoportal plugin inside GeoLibre; timers must be released when a map is closed or replaced.

## History

- geoportal-legacy: in progress since 25 September 2026, wave 3. Approach chosen: a refresh property on the connected layer (interval, view change, push) with the time of the last update; streams were already pushed and only needed the timestamp.
- 13 October 2026: geoportal — map and dashboard behaviour, rebuilt as a layer property handled by the Geoportal plugin in GeoLibre and by the dashboards extension.

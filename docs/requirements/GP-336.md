acceptance:
  - From the browser a WMS or WFS request with the session cookie is answered through the gateway, and the same request without a session, or with a forged user header, is refused.
  - GeoServer is not reachable from outside the installation; only the gateway and AuthKey clients reach it.
  - QGIS with a personal AuthKey loads the layers its owner may see, and an unknown or revoked key is refused.
  - A public or external link opens only the resource it names, and requests beyond the organization's quota are refused.
---

From the browser, data travel through a gateway: nginx with `auth_request` in front of GeoServer,
streams, databases and processes, so the data do not pass through Geoportal, which only gives the go
ahead. The gateway handles the session cookie, public and external links, quotas and the access log.
GeoServer accepts the user header from the gateway only and is not reachable from outside. QGIS goes
straight to GeoServer with a personal AuthKey, which GeoServer checks by asking Geoportal; those
accesses stay in the GeoServer logs for now.

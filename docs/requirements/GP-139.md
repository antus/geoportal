The application is built once at the root and the path prefix (for example /geoportal) is read at start
from a configuration property: incoming requests have it stripped, Location headers get it added, and
the web client derives its base from the address of its own startup script. Images and portable
packages can be moved under another path without rebuilding.

## History

- geoportal-legacy: done in v1.4.0, wave 1. A route filter stripped the prefix and a response filter
  rewrote Location headers.
- 13 October 2026: moved — serving the kernel, the shell and extension assets under a runtime prefix is
  generic and Mosaikit does not have it yet (MK-122).

  - Before sending, the commit shows the created, modified and deleted features; after it, WFS answers of the layer contain the changes.
  - Each commit writes one audit entry with the counts of created, modified and deleted features.
  - A commit whose starting version is stale is refused and the session remains intact for a new attempt.
---

An explicit, audited commit writes the session back to the source: the organization's PostGIS table
(or a database table connected by the organization) or a transactional service, behind one
interface, with the comparison shown before sending. A failed commit leaves the session intact; the
starting version is checked so that a stale commit is refused rather than overwriting another
person's work.

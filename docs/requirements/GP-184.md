  - A query on a source that exposes Flight SQL is transferred in Arrow format, and the same query returns the same rows as over JDBC.
  - A source without Flight SQL keeps working over JDBC with no change visible to the user.
  - The browser receives a large result as Arrow and loads it into DuckDB-WASM without a JSON step.
---

The SQL dialect stays, the pipe changes: warehouses and federated engines expose Flight SQL, which delivers columns rather than rows, and an ADBC driver speaks it without rewriting the query executor. The gain is in transfer, about an order of magnitude on results of millions of rows, and it makes the asynchronous path for large results practical. The same format can reach the browser, where DuckDB-WASM reads Arrow directly.

The legacy proofs (F0) showed that GeoServer can run without users of its own: the gateway passes the
user in a header, AuthKey asks Geoportal for QGIS, roles come from a JDBC role service on database
views, GeoFence rules written over REST hold for area, CQL and columns, and static GeoLibre saves
through a plugin. They also fixed two decisions: vectors are written by Geoportal straight into
PostGIS (the Importer refused four formats out of nine and misread a projected GeoJSON), rasters live
on disk in the portable and in the object store on the server. Those decisions stand. What changed is
every integration point: the session is now Mosaikit's, the roles live in kernel tables under
row-level security, the AuthKey mapper must call an extension endpoint, and GeoLibre runs inside a
Mosaikit extension frontend. This requirement repeats the critical proofs on the `geoportal-server`
distribution before GP-334, GP-335 and GP-336 build on them, keeping the known traps: the GeoServer
authentication cache (60 s), gateway and AuthKey reading roles from one source, re-reading every
GeoFence rule after writing it, and a closed default when GeoFence is absent.

  (GeoServer 15/15, GeoLibre 13/13, Importer formats); the REST role service proved unnecessary, the
  relay accepts an HMAC identity token signed by Geoportal instead of OIDC, the portable stack started
  in 14 s and 514 MB.
- 13 October 2026: geoportal — the decisions are kept, but the proofs ran on the old session and
  database, so the integration points are re-proved on the Mosaikit stack; estimate reduced because
  the method and the suites already exist.
- 2026-10-13: in progress, phase F01 of the master plan: the October proofs repeated on the Mosaikit
  stack (a Mosaikit installation with the catalog extension, PostGIS, GeoServer with GeoFence,
  AuthKey and the Importer, nginx), each by a script, with a report and the decisions it settles.
- 2026-10-13: F01 proofs run on the Mosaikit stack (`prototypes/f01`, RESULT.md), twice, the first
  from empty volumes. Hold: header only from the gateway (Tomcat lets in only the gateway's address),
  `auth_request` on the Mosaikit session (10 s go-ahead cache), GeoFence by REST (80 of 200 rows,
  column hidden, deny by default), AuthKey through the catalog (same features as the session, revoked
  key stops in 60 s), roles by the JDBC role service on read-only views of the kernel tables (REST
  fallback works but renames roles). The Importer loads 3 of 8 files right: vectors stay direct
  PostGIS writes. Open for F03/F04: a service identity and server-side session revocation in
  Mosaikit, published kernel views for roles, the catch-all ALLOW of the distribution, the proxy URL
  of the QGIS door. GeoLibre inside the shell is not part of F01.
- 2026-10-13: done. `prototypes/f01/run.py` repeats the proofs on the Mosaikit stack: the header only
  from the gateway, nginx auth_request on the session, GeoFence rules by REST (area, CQL, hidden
  columns, deny by default), AuthKey through an extension endpoint with revocation within 60 s, and
  roles from a JDBC role service on views all hold; the Importer does not (3 files out of 8) and
  direct PostGIS writes do (ADR-0015, ADR-0016; report in `prototypes/f01/RESULT.md`). The fourth
  criterion, GeoLibre inside the shell, needs the maps extension and moved to GP-340.

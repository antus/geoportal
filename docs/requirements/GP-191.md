  - A saved query set to materialize hourly is executed on the source once an hour, whatever the number of open dashboards that read it.
  - Every panel reading an extract shows the time the extract was last refreshed.
  - The policy of a connection (query in place, materialize with cadence, extract once) is visible on the source.
---

A saved query of the SQL workspace becomes a materialized table or a columnar extract with its own cadence, and dashboard panels read that. Today each widget queries the source on every opening; on a pay-per-use warehouse a dashboard left open on a control-room screen is an unplanned running cost. With the extract the same screen costs one refresh an hour instead of one per look. Freshness is stated on the panel: a number from materialized data without its time is a wrong number that looks right.

acceptance:
  - A process run with partitioning on a tile grid executes the graph once per tile, in parallel, and merges the results.
  - A run interrupted after most partitions resumes from the unfinished partitions, not from the start.
  - A finished run reports how many partitions it touched and which were empty.
---

The same graph runs on a grid of tiles or on table partitions, in parallel, with a checkpoint per
partition: a job that fails at ninety percent restarts from there, and a finished one says how many
partitions it touched and which were empty. It makes in-house everything not worth delegating, and
makes a failure on large volumes readable; today a long run that stops leaves nothing reusable.

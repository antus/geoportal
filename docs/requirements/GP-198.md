  - Uploading an IFC file starts an asynchronous conversion job whose queue position, progress, retries and log the user can see.
  - The job produces a 3D Tiles tileset that the map engine loads, and picking an element returns its IFC properties carried as per-element metadata.
  - The conversion completes with no outbound network call when the external conversion service is not configured.
  - When an external conversion service is configured, the same upload can be sent to it instead, and the result is stored the same way.
---

Geoportal converts IFC models itself: it reads the IFC, extracts the geometry and tessellates it into
3D Tiles that keep the metadata of each element. The conversion runs as an asynchronous job on the
process machinery Geoportal already has (queue, progress, retry, log, audit); an external conversion
service remains an alternative executor, not the only one. This is what makes BIM usable where data may
not leave the organization: closed installations, separated networks, public bodies that cannot upload
their assets to a third-party service. The source file is always kept, so a revision can be converted
again when the chain improves. The conversion is a service of its own; it is a natural candidate for the
heavy-processing sidecar planned for processes.

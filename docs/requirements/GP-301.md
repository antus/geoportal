  - For a CSV the connection step states the geometry strategy found (WKT, GeoJSON column, latitude/longitude pair) or that none was found, and a CSV without geometry does not offer "create a map".
  - For a REST endpoint and for SSE, Kafka and WebSocket streams the connection step shows a sample of the response or messages and classifies its shape.
  - For a database the list of tables marks which ones have a geometry column, and only those offer "create a map".
  - Live sources (for example aircraft, ships, earthquakes) appear as always-active sources with a preview of their data and their declared configuration.

The capabilities of a source (usable in a map, a dashboard, a process) were declared per type, which is
guessing: a CSV without coordinates is not a map layer, a REST path can serve anything, a table without
geometry cannot be drawn. The rule is to **look** instead of deducing: read the header and first rows of
a CSV, show a sample of a REST response or of stream messages, list the tables of a database with their
geometry columns. What was found is shown on the connection step and in the detail panel, where the
three "create" buttons light up on it. Live sources are single-instance adapters, always active, with a
data preview; those not based on an ordinary connection are labelled Custom. API keys of live sources
stay on the server.

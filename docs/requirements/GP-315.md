  - In each context the Type filter and the parts offered are limited to what that editor can use.
  - The picker supports single and multiple choice, and returns a reference to the source and its part, so that a later change of the source address is followed by the users of the reference.
  - The filter column can be widened by dragging or with the keyboard, so that long type names are readable.

The question "what data do I put here" had three different answers: a catalog-shaped picker in maps, a
list of twelve protocols to choose before searching in dashboards, and twenty-five protocol nodes in
processes. One picker, offered by the catalog extension to the other editors, answers it everywhere,
with a **context** (map, dashboard, process) that filters types and parts through the capabilities of
each source. It is a modal wide enough for the three-column layout, and it is the catalog view itself,
not a copy of it: every improvement of the catalog page reaches the three editors. It returns a
reference, not a copied address.

  - At 390 px width no Geoportal page (lists, catalog, map, dashboard, process editors) scrolls horizontally.
  - Below 768 px a table of a Geoportal page shows each row as a card with the column name in front of each value.
  - Below 768 px the filter column of a list and the side panel of an editor open as a bottom sheet that closes with Escape or a downward swipe.
---

The whole application must adapt to the window, not a reduced site and not four privileged paths: an interface that works on four screens teaches distrust of the others. Three breakpoints, grids that size themselves by minimum readable cell width instead of extra breakpoints, tables that stack below the medium breakpoint, and side panels that become bottom sheets. The shell frame (bottom bar for destinations, bottom sheet component, breakpoint tokens) is generic; this requirement covers the Geoportal pages and editors.

## History

- geoportal-legacy: done in v1.4.0, wave 2. Measured first at five widths; three declared breakpoints, intrinsic grids, stacked tables, one bottom sheet component and the bottom bar; it cost less than estimated because earlier shell work had done part of it.
- 13 October 2026: split — the responsive frame and bottom sheet belong to the Mosaikit shell and UI kit; Geoportal keeps its own pages. Estimate lowered from 20–30 days because the shell part moves to Mosaikit.

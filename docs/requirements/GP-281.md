  - One command produces the delivery set (quality plan, test plan and report, operations manual, navigable API documentation, maintenance plan with service levels, accessibility statement, data-processing documents, training plan, migration and exit plans, bill of materials with licences) for a given release.
  - The test report in the set lists the suites run on that release with their outcome, and changes when a suite fails.
  - The API documentation and the bill of materials in the set match the OpenAPI descriptions and the SBOM published with the same release.
  - Documents that cannot be generated, such as the data protection impact assessment, come as fillable templates with a note saying who signs them.

The documentation that makes the product work is not the documentation that delivers it. A public body asks for the full set at the time of the offer: quality plan, test plan and report, operations manual, navigable API documentation, maintenance plan with service levels and intervention windows, accessibility statement in the official model, data-processing documents, training plan with material, migration and exit plans, bill of materials with licences. A private customer asks for a shorter but non-empty set. The set is generated from the sources of the product, because a hand-written set diverges at the first version.

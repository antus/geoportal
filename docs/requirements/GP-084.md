  - A rule "value above a threshold for N minutes" on a live stream raises one alert when the condition holds for N minutes and none before.
  - A rule "no data for N minutes" raises an alert when a network stops sending, and the alert returns to normal when readings resume.
  - A rule "enters an area" on a moving feature raises an alert when a position inside the drawn polygon arrives.
  - The same rule model evaluated on a PostGIS layer on a schedule raises the same alert as on the stream.
---

Geoportal ingests real-time data and runs scheduled jobs, but it cannot watch a value and warn someone, which is the difference between a monitoring product and a viewer. A rule is written as a sentence: when a value exceeds a threshold, stays out of range for a duration, stops arriving, or enters an area. One rule model has two evaluators: stream rules are evaluated on arrival by the existing broker consumers, layer and query rules on a schedule through the process scheduler. A rule has a state (alarm, acknowledged, back to normal), so a threshold exceeded for six hours yields one alert with a history, not hundreds of notifications. Rules only read observations marked good by the quality checks. Rules, alerts and their state are per organization; alarms are audited.
